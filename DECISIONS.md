# Decisiones y límites de la primera versión

- **Montos:** enteros en centavos; cantidades como cadenas decimales con hasta tres decimales. BigInt multiplica milésimas por centavos y redondea half-up una sola vez por línea. Límite por importe/línea: Q999,999,999.99. El caso 35 × Q71.99 = Q2,519.65 está probado.
- **Pagos:** el estado se deriva de abono acumulado y monto acordado. Una edición actualiza el abono del compromiso; no representa un libro contable inmutable de transacciones individuales. Para varios períodos, crea un registro por período.
- **Compromisos:** compras aportan solamente saldo; mano de obra aporta acordado menos abonado; pendientes no cancelados ni ya comprados/recibidos/completados aportan estimación. La conversión enlaza ambos documentos en un batch. Si eliminas una compra convertida, la estimación anterior no se reactiva automáticamente; revisa el pendiente antes de volver a comprometer dinero.
- **Conflictos:** formulario verifica la versión vista; reglas exigen incremento exactamente de uno. No hay sobrescritura silenciosa desde un dispositivo atrasado. No se usa transacción de lectura online para guardar porque impediría trabajo sin red. Un rechazo posterior a reconectar revierte la vista provisional y solicita reabrir el registro.
- **Fecha:** campos locales se interpretan en America/Guatemala (UTC−06:00). ICS se exporta en UTC con final una hora después y alarma. No hay notificaciones push ni garantías sobre las alertas que configure el calendario del teléfono.
- **Escala y Spark:** se escuchan las colecciones completas del proyecto activo para tenerlas offline; apropiado para obras personales, no para millones de registros. No se habilitan servicios de pago. Vigila las cuotas gratuitas en Firebase Console.
- **Importación:** JSON versión 1, hasta 10 MB y 450 registros por operación. Una obra nueva evita colisiones con datos actuales. Batch atómico: éxito completo o ningún cambio en servidor. Conserva borrados lógicos y remapea IDs. No hay importación parcial de archivos grandes.
- **Catálogos:** tipos/colecciones para Supplier y Material preparados; compras aceptan nombres de material/proveedor para evitar configurar catálogos antes de registrar. El comparador agrupa por nombre y unidad; no convierte unidades ni normaliza sinónimos.
- **Adjuntos:** no se capturan fotos ni se usa Storage. Se pueden incorporar referencias a adjuntos en una migración futura con autorización y reglas específicas.
- **Offline:** solo datos previamente consultados, mismo dispositivo y navegador de confianza. La caché de cada UID está separada, persiste después de salir y no está cifrada. El botón de salida advierte si hay escrituras pendientes. No se promete sincronización con el navegador cerrado.
- **PWA:** shell local sin fuentes ni scripts CDN; iconos propios generados como PNG. Service worker de producción y manifest. Instalación de iOS requiere acción manual; las pruebas automatizadas verifican manifest y recarga offline, no el diálogo nativo de cada teléfono.
- **Borrado:** lógico en interfaz, confirma antes; eliminar obra la oculta y conserva sus subcolecciones. Firestore no elimina subcolecciones automáticamente. Exporta antes de borrar; en esta versión no hay papelera visible.
- **Docker:** imagen única para desarrollo, emuladores, build y Chromium; mayor descarga inicial a cambio de un entorno sin herramientas globales. Node/JDK y dependencias directas fijados, lockfile versionable. Repositorio inicial vacío: no había historial ni cambios que preservar.
